# VLADYERIK Arcade Online — Sites test

Site Worker for the trial room. It uses the same Sites Worker + D1 pattern recovered from Truco/UNO/Chinchón/Loba/Culo Sucio. D1 is authoritative; the browser polls the same-origin HTTP API. No Node server, third-party hosting or WebSocket endpoint is required.

`index.html` is the Site UI, `client.js` handles player presence, rooms, invitations and all six games. The Worker validates turns and moves before writing room state to this trial project's existing D1 `online_*` tables. Argentine Draughts uses a 10×10 board, 15 pieces per side, mandatory captures, maximum capture value, multi-capture sequences, flying kings and promotion. Ludo Matic supports 2–4 online seats, private/public rooms, invitations and solo play against 1–3 computer opponents. Tutti Frutti and ¡Basta! support local play against the computer and online rooms, use separate category sets, timed rounds, hidden answers until reveal and unique/repeated scoring; online rooms support up to eight seats. Estanciero supports local play against the computer plus 2–6 online seats, property and railway purchases, rent, start salary, bank/tax/chance spaces, one estancia upgrade per field, police turns, bankruptcy and a last-player victory. Party-game rules live in `party-engine.js`; the build embeds the same rules in the browser bundle and Worker. All three games retain online multiplayer and also include client-side play against the computer without creating a room or using D1 during solo play. Existing D1 tables and Worker bindings are reused; no migration is needed.

From this directory, run `npm run build`, `npm run validate`, and `npm test`. Package/deploy only from the Sites source checkout after its `.openai/hosting.json` contains the project ID returned by Sites and the `DB` binding.
