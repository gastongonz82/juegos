# VLADYERIK Arcade Online — Sites test

Site Worker for the trial room. It uses the same Sites Worker + D1 pattern recovered from Truco/UNO/Chinchón/Loba/Culo Sucio. D1 is authoritative; the browser polls the same-origin HTTP API. No Node server, third-party hosting or WebSocket endpoint is required.

`index.html` is the Site UI, `client.js` handles player presence, rooms, invitations and all six games. The Worker validates turns and moves before writing room state to this trial project's existing D1 `online_*` tables. Argentine Draughts uses a 10×10 board, 15 pieces per side, mandatory captures, maximum capture value, multi-capture sequences, flying kings and promotion. Ludo Matic supports 2–4 online seats, private/public rooms, invitations and solo play against 1–3 computer opponents. Tutti Frutti and ¡Basta! use separate category sets, simultaneous timed rounds, hidden answers, unique/repeated scoring, public/private rooms and up to eight seats. Estanciero supports 2–6 seats, property and railway purchases, rent, start salary, bank/tax/chance spaces, one estancia upgrade per field, police turns, bankruptcy and a last-player victory. Party-game rules live in `party-engine.js`; the build embeds the same rules in the browser bundle and Worker. Tutti Frutti, ¡Basta! and Estanciero are online multiplayer games and require at least two connected players. Existing D1 tables and Worker bindings are reused; no migration is needed.

From this directory, run `npm run build`, `npm run validate`, and `npm test`. Package/deploy only from the Sites source checkout after its `.openai/hosting.json` contains the project ID returned by Sites and the `DB` binding.
